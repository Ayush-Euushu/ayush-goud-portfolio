# Build Rules

## Content Accuracy

Use only information provided in PRD.md.

Never invent:

- Achievements
- Awards
- Certifications
- Testimonials
- Clients
- Companies
- Project results
- Statistics
- User numbers
- Technologies
- Dates
- Academic results
- Experience claims

If information is missing, do not guess.

## Personal Branding

The portfolio should present Ayush as:

- A Computer Science student
- Interested in software development
- Interested in programming
- Interested in problem solving
- Interested in data analysis
- Learning AI/ML fundamentals

Do not present him as an expert in technologies where expertise was not stated.

Do not exaggerate internship experience.

## Projects

Use only the three projects provided in PRD.md.

Do not add fake:

- GitHub repositories
- Live demos
- Project statistics
- Accuracy percentages
- User counts
- Business results
- Technologies

## Navigation

All navigation links must point to real sections.

The top navigation should work on desktop and mobile.

## Responsive Design

The website must:

- Work on desktop
- Work on mobile
- Avoid horizontal scrolling
- Keep text readable
- Keep buttons usable
- Prevent images from overflowing
- Keep navigation accessible

## Accessibility

- Maintain readable contrast.
- Use meaningful link/button text.
- Provide appropriate alternative text for meaningful images.
- Keep interactive elements keyboard accessible.
- Do not rely only on colour to communicate important information.

## Development

Build the website in stages.

After each major stage:

1. Run the website.
2. Inspect the result.
3. Check for errors.
4. Test the affected functionality.
5. Continue only after the section works.

When fixing an issue, change only what is necessary.

Do not rewrite unrelated sections.

## Visual Consistency

Follow design.md.

Do not introduce unrelated colours, layouts or visual patterns.

Preserve the existing Stitch design direction when implementing it.

## Final Requirement

Before considering the website complete, review it against:

- PRD.md
- design.md
- rules.md

Check both desktop and mobile layouts.
